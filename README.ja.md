# SaaS Web QA Skill

[한국어](README.md) | [English](README.en.md) | 日本語 | [Tiếng Việt](README.vi.md) | [Español](README.es.md) | [Português](README.pt.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Italiano](README.it.md)

WebサイトやSaaSの動作、レスポンシブUI、アクセシビリティを確認する統合スキルです。Anthropic、Vercel、Microsoftなどの公開スキルのワークフローを選んで再構成しています。手順とチェック項目は同梱されていますが、元のスキルやツールはインストールされません。

依頼に応じて、リスクに基づくQA計画、APIの動作確認、既存のPlaywright・Cypressテストのレビュー、失敗原因の調査にも対応します。詳しくは[出典と対象範囲](skills/saas-web-qa/references/sources.md)を参照してください。

ログイン後の点検では、承認済みアカウントの役割とワークスペース、対象の一覧・検索・フィルター、変更後に確認できた範囲を区別します。ブラウザーを分離してもサーバー側のデータは共有される場合があります。

ユーザータイプ別QAでは、10の想定ユーザーが実ブラウザーで操作します。対応環境では役割ごとにサブエージェントが結果とスクリーンショットを集め、修正依頼時は同じ操作を再確認します。詳しくは[手順](skills/saas-web-qa/references/persona-journeys.md)を参照してください。

## QAの進め方

- **診断・修正・再確認:** 通常のQAでもユーザータイプ別QAでも、修正を依頼された場合は対象範囲の問題を修正し、稼働中のサービスに変更が反映された後、元の問題を再確認します。再確認できない場合は理由と未確認の範囲を報告します。
- **操作経路ごとの確認:** 複数の機能を依頼された場合は、それぞれの開始点と成功基準を定めます。ユーザータイプ別QAでは経路ごとに結果を分け、問題ごとにその手順を評価できた役割数と問題を経験した役割数を記録します。発生数を基準に整理し、深刻な問題は別途強調します。
- **ログイン前後:** ログインが阻まれても承認済みセッションがあれば、ログイン後の機能を別途確認できます。この場合、ログインから続く一連の経路が成功したとは報告しません。

## エージェントにインストールとQAを依頼

以下のように依頼してください。リポジトリがGitHubに公開され、エージェントからアクセスできる必要があります。

```text
https://github.com/Fhwang0926/saas-qa-skills の saas-web-qa を
現在のプロジェクトにインストールし、手順を読んで以下をQAしてください。
インストール済みの場合は依頼した機能があることを確認して使用してください。

対象: 現在のプロジェクトのログイン画面
範囲: PC・モバイル表示、ログイン動作、アクセシビリティ
```

インストールだけが必要な場合は、QAを依頼せずにインストールのみを指定してください。スキルの検出に新しいセッションが必要な場合がありますが、同じセッションでファイルを読めれば、そのまま手順に従えます。

### エージェント向け手順

1. 対象プロジェクトとエージェントを確認し、ユーザーとプロジェクトの指示を読む。`saas-web-qa` がインストール済みなら `SKILL.md` と必要な参照を読み、依頼した機能があるか確認する。名前だけで最新版と判断しない。十分なら再利用し、不足する場合はこのリポジトリのアクセス可能な原本、インストール元、ローカル変更を確認して規則に従い更新する。安全に置き換えられない場合は可能なら原本の手順を直接使う。原本にアクセスできない場合や機能がない場合は制約を報告する。
2. 必要なら対象プロジェクトで下記のコマンドを実行する。対話的な選択ができずエージェントが分かる場合は、そのエージェントだけを指定する。Codexでは `--agent codex -y` を追加する。全体へのインストールを依頼されていなければ `-g` は付けない。環境の権限とツール規則に従う。
3. インストール結果とパスを確認し、`SKILL.md` と必要な `references/` を読む。セッションに登録されていなくてもファイルを読めれば直接手順に従う。インストールのみの依頼ではQAを実行しない。
4. 起動中のサービスと利用可能なブラウザーを優先する。ビルド、テスト、サーバー起動、DB、外部サービスはユーザーとプロジェクトの規則に従う。ツールや権限が不足する場合は、実施範囲と障害を報告し、成功を推測しない。

## 直接インストール

GitHubへの公開後、対象プロジェクトで次を実行します。Node.js 22.20以降が必要です。表示に従ってエージェントを選択してください。

```bash
npx skills add Fhwang0926/saas-qa-skills --skill saas-web-qa
```

ローカルのチェックアウトからインストールする場合は、実際のパスに置き換えます。

```bash
npx skills add /path/to/saas-qa-skills --skill saas-web-qa
```

既定では対象プロジェクトにインストールされます。全体で使用する場合は `-g` を追加してください。必要に応じてエージェントを再起動します。

## 使用例

```text
$saas-web-qa ログイン画面をPCとモバイルで確認し、再現可能な問題を報告してください。
```

### 診断・修正・再確認をまとめて依頼

```text
$saas-web-qa 起動中のサービスを10種類のユーザーとして確認してください。
可能なら役割ごとにサブエージェントを使用し、公開画面と、承認済みアカウントで
ログイン後の主要機能を実際のブラウザーで確認してください。
迷いや障害をスクリーンショットで記録し、問題ごとにその手順に到達した人数と
問題を経験した人数を報告してください。確認された問題をまとめて修正し、
同じ役割と条件で再確認して、解決した問題と残った問題を教えてください。
```

このスキルは手順を提供します。ブラウザー、Playwright、稼働中のアプリ、アカウントは同梱されません。実際の確認には環境とアクセス権が必要です。ユーザーとプロジェクトの規則が優先されます。
