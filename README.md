# SaaS Web QA Skill

한국어 | [English](README.en.md) | [日本語](README.ja.md) | [Tiếng Việt](README.vi.md) | [Español](README.es.md) | [Português](README.pt.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Italiano](README.it.md)

웹사이트와 SaaS 서비스의 브라우저 동작, 화면·반응형 UI, 접근성을 `saas-web-qa` 스킬로 점검합니다. Anthropic, Vercel, Microsoft의 공개 스킬에서 관련 워크플로를 선별해 QA 지침으로 재구성했습니다. 원본 스킬과 외부 도구를 별도로 설치하지 않아도 스킬 지침과 점검 항목을 읽을 수 있습니다.

검색엔진 사이트 등록은 별도 [search-engine-registration](skills/search-engine-registration/SKILL.md) 스킬로 지원합니다. 구글 URL 접두어 등록, 네이버 소유확인, 구글 서치콘솔에서 빙으로 가져오기, 다음 robots.txt 인증을 다룹니다.

요청 범위에 따라 위험도 기반 QA 계획, API 동작 확인, 기존 Playwright·Cypress 테스트 검토와 실패 원인 분석도 지원합니다. [Kimi의 소프트웨어 테스트 스킬 목록](https://www.kimi.ai/ko/resources/software-testing-skills)에서 소개한 관련 프로젝트를 함께 참고했습니다.

로그인 후 점검에서는 승인된 계정의 역할과 워크스페이스, 관련 목록·검색·필터, 데이터 변경 후 확인 범위를 구분해 기록합니다. 브라우저를 분리해도 서버 데이터는 공유될 수 있으므로 병렬 점검 시 충돌 여부도 고려합니다.

사용자 유형별 QA를 요청하면 급한 사용자, 모바일 사용자 등 10가지 역할이 실제 브라우저에서 첫 성공까지의 과정을 살펴봅니다. 로그인 전 화면부터 시작하거나, 승인된 로그인 세션으로 대시보드·설정 등 로그인 후 기능을 확인할 수 있습니다. 가능한 환경에서는 역할별 서브 에이전트로 분담하고, 문제와 스크린샷을 모아 수정 요청 시 재확인합니다. 자세한 절차는 [사용자 유형별 QA](skills/saas-web-qa/references/persona-journeys.md)를 참고하세요.

## QA 진행 방식

- **진단·수정·재확인:** 일반 QA와 사용자 유형별 QA 모두 수정이 요청되면 범위에 맞게 문제를 고치고, 실행 중인 서비스에 반영된 뒤 원래 문제를 다시 확인합니다. 재확인이 불가능하면 이유와 미확인 범위를 보고합니다.
- **여정별 점검:** 여러 기능을 요청하면 각 여정의 시작점과 성공 기준을 따로 정합니다. 사용자 유형별 QA에서는 여정별 결과를 구분하고, 문제마다 해당 단계에 도달해 평가한 역할 수와 문제를 겪은 역할 수를 기록합니다. 발생 빈도를 기준으로 정리하되 심각한 문제는 별도로 강조합니다.
- **로그인 전후:** 로그인 과정이 막혀도 승인된 기존 세션이 있으면 로그인 후 기능을 별도로 확인할 수 있습니다. 이때 로그인부터 내부 기능까지 이어진 전체 여정은 성공으로 처리하지 않습니다.

아래 7개 스킬·스킬 모음의 워크플로를 선별해 하나의 `saas-web-qa` 지침으로 재구성했습니다. 원본 패키지, 전체 규칙, 스크립트와 도구를 그대로 포함하거나 설치하지는 않습니다. 원본 링크와 통합 범위는 [출처](skills/saas-web-qa/references/sources.md)에서 확인할 수 있습니다.

| 공개 스킬·모음 | 이 스킬에 반영한 점검 방식 |
| --- | --- |
| Anthropic `webapp-testing` | 렌더링된 화면을 먼저 살펴보고 사용자 동작과 결과를 확인하는 브라우저 점검 |
| Vercel `web-design-guidelines` | UI, 사용성, 인터랙션, 접근성 검토 |

| `e2e-skills` | 기존 E2E 테스트의 품질 검토와 실패 원인 분석 |

## 에이전트에게 설치와 QA 요청하기

아래 내용을 Codex 등 사용하는 코딩 에이전트에 전달하고 점검할 화면과 범위를 적어 주세요. 저장소가 GitHub에 게시되어 있고 에이전트가 접근할 수 있어야 합니다.

```text
https://github.com/Fhwang0926/saas-qa-skills 의 saas-web-qa 스킬을
현재 프로젝트에 설치하고, 설치한 스킬 지침을 읽어 아래 범위를 QA해줘.
이미 설치되어 있으면 요청한 기능이 있는지 확인하고 사용해줘.

점검 대상: 현재 프로젝트의 로그인 화면
점검 범위: PC·모바일 화면, 로그인 동작, 접근성
```

설치만 원하면 QA 요청 없이 설치만 요청하면 됩니다. 사용하는 에이전트나 프로젝트 정책에 따라 설치 후 새 세션이 필요할 수 있습니다. 같은 세션에서 설치된 파일을 읽을 수 있다면 에이전트가 해당 지침을 직접 읽고 이어서 작업할 수 있습니다.

### 에이전트 실행 지침

사용자가 이 저장소의 스킬 설치와 사용을 요청한 경우:

1. 현재 작업 중인 **대상 프로젝트**와 에이전트를 확인하고, 프로젝트 및 사용자 지침을 읽는다. `saas-web-qa`가 이미 설치되어 있으면 설치 경로의 `SKILL.md`와 필요한 참조 파일을 읽고 이번 요청에 필요한 기능이 실제로 있는지 확인한다. 이름만 같다고 최신 버전이라고 가정하지 않는다. 필요한 기능이 있으면 기존 설치본을 사용한다.
2. 필요한 기능이 없으면 사용자가 지정한 이 저장소의 접근 가능한 버전에서 해당 지침과 참조 파일을 확인한다. 설치본의 출처와 로컬 수정 사항을 살피고 사용자·프로젝트 규칙에 따라 업데이트한다. 기존 내용을 안전하게 교체할 수 없으면 덮어쓰지 말고, 접근 가능한 저장소 지침을 직접 읽어 사용할 수 있는지 확인한다. 원본에도 기능이 없거나 접근할 수 없으면 부족한 기능과 제한을 보고한다. 설치본이 최신이라는 근거가 없으면 최신이라고 말하지 않는다.
3. 설치가 필요하면 대상 프로젝트에서 아래 설치 명령을 실행한다. 대화형 선택이 불가능하고 에이전트 종류를 알고 있다면 그 에이전트에만 설치한다. 예를 들어 Codex는 `--agent codex -y`를 추가한다. 사용자가 전역 설치를 요청하지 않았다면 `-g`는 추가하지 않는다. 설치 권한과 환경의 도구 사용 규칙을 따른다.
4. 설치 또는 업데이트 결과와 스킬 경로를 확인하고 `SKILL.md`와 필요한 `references/` 파일을 읽는다. 세션에 스킬이 자동 등록되지 않아도 파일을 직접 읽을 수 있으면 그 지침에 따라 같은 세션에서 요청된 QA를 진행한다. 설치만 요청받았다면 QA는 실행하지 않는다.
5. 실행 중인 서비스와 사용 가능한 브라우저를 우선 사용한다. 빌드, 테스트, 서버 시작, DB 및 외부 서비스 작업은 사용자와 대상 프로젝트의 규칙을 따른다. 필요한 도구나 접근 권한이 없으면 설치 성공이나 QA 완료를 추정하지 말고 막힌 지점과 수행한 범위를 알린다.

## 직접 설치

저장소를 GitHub에 올린 후 대상 프로젝트에서 한 번 실행합니다. Node.js 22.20 이상이 필요하며, 설치 중 사용할 에이전트를 선택할 수 있습니다.

```bash
npx skills add Fhwang0926/saas-qa-skills --skill saas-web-qa
```

아직 GitHub에 올리지 않은 로컬 저장소로 설치하려면 대상 프로젝트에서 아래 경로를 실제 저장소 경로로 바꿔 실행합니다.

```bash
npx skills add /path/to/saas-qa-skills --skill saas-web-qa
```

기본 설치 범위는 명령을 실행한 프로젝트입니다. 다른 프로젝트에서도 공통으로 사용하려면 `-g` 옵션을 추가합니다. 설치 후 에이전트를 다시 시작해야 스킬이 표시될 수 있습니다.

## 사용 예시

### 검색엔진 등록 스킬

QA 스킬과 별도로 필요한 프로젝트에 설치합니다. 아래의 QA 설치·실행 지침과 구분하여 `search-engine-registration`의 지침을 읽고 사용합니다.

```bash
npx skills add Fhwang0926/saas-qa-skills --skill search-engine-registration
```

```text
$search-engine-registration https://example.com 사이트를
구글 URL 접두어, 네이버, 빙 Search Console 가져오기, 다음 웹마스터에 등록해줘.
기존 인증 설정을 확인하고 필요한 코드 변경과 서비스별 남은 단계를 알려줘.
```

로그인·PIN 입력·이용 동의에 사용자 참여가 필요할 수 있습니다. 실제 등록에는 공개 사이트 반영과 서비스별 인증 성공 확인이 필요하며, 이 저장소에 스킬을 추가하는 것만으로 사이트가 등록되지는 않습니다.

### 웹 QA 스킬

```text
$saas-web-qa 로그인 화면을 PC와 모바일에서 점검하고 재현 가능한 문제를 알려줘.
```

```text
$saas-web-qa 현재 실행 중인 서비스의 회원가입 흐름과 접근성을 확인해줘.
```

### 한 번에 진단·수정·재확인

```text
$saas-web-qa 현재 실행 중인 서비스를 10가지 사용자 역할로 점검해줘.
가능하면 역할별 서브 에이전트를 사용하고, 로그인 전 화면과 승인된 계정의
로그인 후 핵심 기능을 실제 브라우저에서 확인해줘.
막히거나 헷갈리는 지점은 스크린샷과 함께 기록하고, 문제별로 도달한 역할 수와
문제를 겪은 역할 수를 정리해줘. 확인된 문제를 한 번에 수정한 뒤 같은 역할과
조건으로 다시 확인하고, 해결된 문제와 남은 문제를 알려줘.
```

스킬은 지침을 제공하며 브라우저, Playwright, 실행 중인 서비스, 계정 등을 함께 설치하거나 제공하지 않습니다. 실제 확인에는 해당 환경과 필요한 접근 권한이 있어야 합니다. 대상 프로젝트와 사용자의 테스트·DB·외부 서비스 사용 규칙이 우선합니다.

참고한 원본과 통합 범위는 [출처](skills/saas-web-qa/references/sources.md)에 정리했습니다.
